# แผนเฟส Web Sandbox — Synapta Lab (v0.0.4)

สถานะ: **อนุมัติแล้ว 2026-11-15** — ทำตามลำดับ M1 → M6

## เป้าหมาย

ตัวจำลองเครือข่าย Synapta แบบ Cisco Packet Tracer ใช้งานผ่านเว็บ

- ลาก node และ "วง" (เหมือน switch ใน Packet Tracer) ลงบนผัง แล้วลากสายจาก node ไปที่วง
- ใน node วงเดียวกันเห็นกันและต่อตรงถึงกันหมด node ที่อยู่หลายวงเป็นสะพานข้ามวง
- **ข้ามวงต้องส่งงานได้จริง** ผ่าน node ที่เป็นสะพาน ซึ่งต้องเพิ่มความสามารถนี้ให้ protocol (ดู "การส่งต่อข้ามวง")
- สั่งงาน ดูข้อความวิ่งตามสาย ดับ node ตัดสาย แล้วดูว่าเครือข่ายรับมือยังไง
- มี node กี่ตัวก็ได้ ข้อจำกัดมีแค่แรงเครื่อง และขีดจำกัดของ protocol ที่ตัวจำลองจะวัดให้เห็น

ตัวจำลองต้องตรงกับ protocol จริง: node ทุกตัวคือโค้ด `synapta-core` ตัวจริง คุยกันผ่าน TCP บน loopback จริง
เข้ารหัสและยืนยันตัวตนจริง ส่วนที่จำลองมีแค่ "ใครต่อถึงใครได้" (วง) และค่าทรัพยากร (mock เหมือนเดิม)

## ข้อตกลงที่ได้จากการคุย

| เรื่อง | ตกลง |
|---|---|
| เข้าเว็บจากไหน | 127.0.0.1 และ IP ของ Tailscale ของเครื่องนี้เท่านั้น ไม่ฟังบน 0.0.0.0 |
| ความปลอดภัยของหน้าเว็บ | ไม่ต้องมีรหัส (Tailscale กันคนนอกให้แล้ว และเป็นแค่ตัวจำลอง) |
| node อยู่ที่ไหน | ทุกตัวในเครื่องนี้ บน loopback · node ข้ามเครื่องจริงยังเป็นเฟสถัดไป |
| จำนวน node | ไม่จำกัด |
| เส้นในผัง | node ต่อเข้า "วง" · ในวงเห็นกันหมด · ข้ามวงผ่าน node ที่อยู่หลายวง |
| ส่งงานข้ามวง | ทำในเฟสนี้เลย (เพิ่มเข้า protocol) |
| ดูข้อความ | ทั้งโหมดสด และอัดไว้แล้วเล่นย้อนทีละข้อความ |

## ภาพรวม

```
เบราว์เซอร์ (มือถือ/PC ในวง Tailscale)
      │ HTTP
      ▼
synapta-lab  ── ฟังที่ 127.0.0.1 และ IP Tailscale
  ├─ ผัง: node, วง, สาย          (เก็บ/โหลดเป็นไฟล์ JSON)
  ├─ ประตูเครือข่าย: ตัดสินว่า node ไหน dial ถึงใครได้ตามวง
  ├─ บันทึกข้อความ: รับรายงานจากทุก node เก็บไว้ให้เล่นสด/ย้อน
  └─ node-1 … node-N   ← synapta-core ตัวจริง รันในโปรแกรมเดียวกัน
                         แต่ละตัวมี 127.x.y.z ของตัวเอง, TCP จริง, Noise จริง
```

- **node รันในโปรแกรมเดียว** ไม่แยก process: ถึงจะมีเป็นร้อยตัวได้ · lab สั่ง node ผ่าน `NodeHandle` ตรง ๆ
  จึงไม่ต้องเปิด HTTP API ของ node เลย (ปัญหาเดิม "token ของ node ทำได้ทุกอย่าง" จึงไม่เกิดในตัวจำลอง)
- **แต่ละ node มี IP loopback ของตัวเอง** (127.0.0.0/8 bind ได้ทุกตัวบน Windows) ทั้งตอนฟังและตอน dial
  — ถ้าทุกตัวใช้ 127.0.0.1 ร่วมกัน port ชั่วคราวของ Windows (~16k) จะหมดเมื่อวงใหญ่ เพราะในวงต่อกันครบทุกคู่

## งานใน protocol (synapta-core) — wire version 4

### 1. ประตูเครือข่าย (dial gate) — ไม่เปลี่ยน wire

- การ dial ทุกครั้งผ่าน `Connector` ที่ส่งเข้ามาตอน start · ค่าปกติ = `TcpStream::connect` ตามเดิม
- lab ส่ง connector ของตัวเอง: dial ได้เฉพาะ node ที่อยู่วงเดียวกัน ไม่งั้นได้ "unreachable"
  (รอจน `connect_ms` เหมือนเครื่องที่ติดต่อไม่ได้จริง)
- ตัดสาย/ย้ายวง: connector ถือ handle ของทุก connection ที่เปิดผ่านมัน และปิด connection ของคู่ที่ไม่อยู่วงเดียวกันแล้วทันที
- ทำไมไม่ใช้ proxy กลาง: ในวงต่อครบทุกคู่ proxy ต้องมีหลักหมื่นตัว และเพิ่มทางที่ protocol จริงไม่มี

### 2. รายงานข้อความ (trace) — ไม่เปลี่ยน wire

- node ส่งเหตุการณ์ "ส่ง/รับ frame อะไร ถึงใคร เวลาไหน request id อะไร" ออกทางช่อง broadcast แบบมีเพดาน
  (ช่องเต็ม = ทิ้ง trace เก่า ไม่ทำให้ node ช้าลง) · ค่าปกติปิดอยู่ ไม่มีต้นทุนใน production
- เก็บสรุปก่อนเข้ารหัส (ชนิด, method, ขนาด, ผลสำเร็จ/error) ไม่เก็บ input เต็ม
- รวม handshake, advert, ping, request/response, relay และ link ขึ้น/ลง

### 3. บัตรสมาชิก (membership card) — แก้ปัญหา "เพิ่ม node ต้องแก้ config ทุกตัว"

- เครือข่ายมี "กุญแจเจ้าของ" (Ed25519) · เจ้าของออกบัตรให้ node: `{node_id, public_key, network, expires}` + ลายเซ็น
- config ใหม่ `[[trust_authority]]` · node ยอมรับใครก็ได้ที่มีบัตรถูกต้องจากเจ้าของที่ตัวเองเชื่อ
  (trust list แบบเดิมยังใช้ได้ควบคู่)
- hello ใน handshake และ advert แนบบัตร → node ที่ไม่เคยเจอกันตรวจ advert ที่ส่งต่อข้ามวงมาได้
  (จำเป็นสำหรับข้ามวง: A ต้องตรวจลายเซ็นของ Z ที่ไม่เคยต่อกันตรง)
- lab เป็นเจ้าของเครือข่าย ออกบัตรให้ทุก node ที่สร้าง
- **ไม่รวมในเฟสนี้:** เพิกถอนบัตรก่อนหมดอายุ · บันทึกเป็นข้อจำกัดใน roadmap

### 4. การส่งต่อข้ามวง (relay)

**รู้เส้นทาง (link-state แบบ OSPF ต่อจากของเดิม)**
- advert เพิ่ม `neighbors`: node ที่มี link READY ด้วย · link ขึ้น/ลงทำให้ออก advert ใหม่ (ผ่านตัวรวม `advert_min_interval_ms` เดิม)
- ใช้เส้นเชื่อมเฉพาะที่ทั้งสองฝั่งประกาศถึงกัน · หาเส้นทางสั้นสุด (นับ hop, เสมอกันเลือกตาม node id ให้ผลตายตัว)
  คำนวณใหม่เมื่อ registry เปลี่ยน

**ส่งต่อทีละ hop**
- request ใหม่ `relay { to, ttl, envelope }` · node กลางส่งต่อไป hop ถัดไปทาง link READY ของตัวเอง ลด ttl (สูงสุด 8)
- error ใหม่: `unreachable` (ไม่มีทางไปต่อ), `ttl_exceeded` · เวลาที่เหลือลดลงทุก hop ไม่ให้รอซ้อนเกิน `request_ms`
- ส่งต่อได้เฉพาะ invoke และ job.* · ping กับ adverts.sync ไม่ข้าม hop

**ปลายทางเชื่อได้ว่าใครสั่ง และต้นทางเชื่อได้ว่าใครตอบ**
- ต้นทางเซ็น envelope `{from, to, nonce, expires, request}` · ปลายทางเซ็นคำตอบ (อ้าง nonce เดิม)
- ทำไม: ถ้าไม่เซ็น node กลางอ้างเป็นใครก็ได้ — allow list ของ capability ที่ตรวจ "ใครเรียก" จะใช้ไม่ได้
  และ node กลางแก้ผลลัพธ์ได้ · ปลายทางจำ nonce ไว้จนหมดอายุ กันส่งซ้ำ
- ไม่เข้ารหัสปลายทาง-ปลายทาง: node กลางเป็นสมาชิกที่เชื่อถืออยู่แล้ว และถูกเลือกไปรันงานเดียวกันได้อยู่แล้ว
  (link แต่ละช่วงยังเข้ารหัสด้วย Noise ตามเดิม)

**routing**
- node ที่ไปถึงได้ผ่าน relay เป็นผู้สมัครด้วย · คะแนนบวกโทษตามจำนวน hop · `routing/explain` แสดงเส้นทาง
- ตรวจ `executed_by` เทียบกับปลายทาง (เดิมเทียบกับ peer ของ link)

**version:** `WireRange::SUPPORTED = {4,4}` · node v0.0.3 ได้ `version_mismatch` ตามระบบที่ทำไว้ใน v0.0.3
(ยังไม่มีเครื่องที่ใช้งานจริง จึงไม่เก็บทางเดินของ wire 3 ไว้)

## synapta-lab (crate ใหม่ `crates/synapta-lab`)

- เปิดด้วย `synapta-lab` → หา IP Tailscale เอง (ช่วง 100.64.0.0/10) หรือระบุ `--listen` · ไม่มี Tailscale = ฟังแค่ 127.0.0.1
  · ปฏิเสธ 0.0.0.0 และ address ที่ไม่ใช่ loopback/Tailscale
- ข้อมูลของรอบอยู่ใน temp dir ของรอบนั้น (key, บัตร, log, บันทึกข้อความ) · ปุ่ม reset ลบทิ้ง
- ทุกคนที่เปิดเว็บเห็นผังชุดเดียวกัน
- API ของ lab (JSON) + บันทึกข้อความดึงแบบ cursor (`?after=<ลำดับ>`) ซึ่งใช้ได้ทั้งโหมดสดและย้อน
- HTTP: ใช้ server ของ gateway ที่มีอยู่ โดยขยายให้รับ IP Tailscale และส่งไฟล์หน้าเว็บได้
  (ถ้าไม่พอสำหรับร้อย node จะเสนอเปลี่ยนก่อนทำ)

## ขีดจำกัดที่รู้ล่วงหน้า (ตัวจำลองจะวัดให้เห็น ไม่ได้ซ่อน)

- ในวงเดียว node ต่อกันครบทุกคู่: N ตัว = N(N−1)/2 connection และ heartbeat ทุกเส้น · advert ท่วมทุก node
  → วงใหญ่มากจะหนักจริง เป็นขีดจำกัดของ protocol ตอนนี้ ไม่ใช่ของตัวจำลอง
- หยุดเวลาจริงไม่ได้ (node ทำงานตามเวลาจริง) · "ทีละสเต็ป" คือเล่นย้อนจากที่อัดไว้
- ทรัพยากรยังเป็น mock เหมือนเดิม

## ไม่รวมในเฟสนี้

- node ข้ามเครื่องจริง (เฟสถัดไป Tailscale)
- เพิกถอนบัตรสมาชิกก่อนหมดอายุ
- ให้ผู้ใช้เขียน capability เอง (= รันโค้ดคนอื่นบนเครื่อง ขัดข้อห้าม)
- จำลองความหน่วง/packet loss ของสาย (เพิ่มทีหลังได้ใน connector ถ้าต้องการ)

ตัดสินใจระหว่างทาง (M4–M6):
- **HTTP server แยกใน lab** ไม่แก้ของ gateway — gateway ต้องเข้ม (token + Host loopback) เพราะคุม node จริง
  lab ไม่มี login ตามที่ตกลง เหลือกันอย่างเดียว: คำขอที่เปลี่ยนอะไรต้องเป็น `application/json` (กันเว็บอื่นในเบราว์เซอร์เดียวกันสั่ง lab)
- หา IP Tailscale ด้วย `tailscale ip -4` (ไม่ใช้ท่า UDP connect เพราะต้อง bind 0.0.0.0 ชั่วขณะ)
- **ตัวจำลองเครือข่ายเปลี่ยนจาก TCP loopback เป็นท่อในหน่วยความจำ** (`tokio::io::duplex`): วัดได้ว่า Windows
  เปิด connection loopback ได้ราว 74 ครั้ง/วินาที วง 150 ตัวต้องใช้ ~44,000 connection — ทดสอบ OS ไม่ใช่ protocol
  handshake/เข้ารหัส/framing ยังเป็นของจริงทั้งหมด
- binary ของ lab ใช้ **mimalloc** — heap ปกติของ Windows ล็อกชนกันจนวง 100 ตัวต่อไม่ติด (วัดแล้ว: ใส่ mimalloc ต่อครบใน ~1 วินาที)

แก้ใน protocol ที่ผังใหญ่เผยออกมา (ยังเป็น wire 4 เพราะยังไม่ออกรุ่น):
1. `adverts.sync` ส่งรายการเวอร์ชัน แล้วส่งเฉพาะ advert ที่อีกฝั่งขาด (เดิมส่งทั้งฐานข้อมูลทุกครั้งที่ลิงก์ขึ้น)
2. ไม่ flood advert ซ้ำไปหาเพื่อนบ้านของต้นทางและของคนที่ส่งต่อมา (เดิม 1 advert กลายเป็น ~N² ข้อความในวงที่ทุกตัวต่อกันหมด)
3. advert ที่ไม่ใหม่กว่าที่มี ทิ้งก่อนตรวจลายเซ็น (ปลอดภัย: ตัวปลอมที่อ้างว่าใหม่กว่ายังโดนตรวจ)
4. ช่วงพักระหว่าง advert ยาวขึ้นตามจำนวนลิงก์ (`advert_min_interval_ms` ต่อ 10 ลิงก์)
5. advert ที่มาซ้ำไม่เร่ง dialer อีก — เร่งเฉพาะเมื่อที่อยู่เปลี่ยน
6. trace รายงาน "ส่ง" ก่อนเขียน (เดิมฝั่งรับตอบกลับก่อนฝั่งส่งรายงาน ทำให้ลำดับในบันทึกกลับหัว)

ผลวัด (เครื่องนี้ 16 core, release, ทุก node ใน process เดียว):
| ผัง | ผล |
|---|---|
| วงเดียว 30 ตัว | ต่อครบ 0.5 วินาที (ก่อนแก้: ต่อไม่ครบเลย) |
